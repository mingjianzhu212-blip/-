## 0. 双线模式与权限边界

- **主线 A**：现有游戏开发，最高优先级；保留全部既有进度、任务上下文、文件改动、测试与待办。

## 1. 即梦官方接入方式调研（2026-11-03 首轮，已核实）

结论：存在**两条官方路径**，均来自火山引擎/即梦官方文档与官网。

### 路径一：消费级网页/客户端（人工操作）
- 入口：`https://jimeng.jianying.com/`（即梦AI · 即刻造梦）。
- 形态：网页端 + 抖音内置小程序 + PC 客户端 + 移动端 APP，多端同步。
- 适用：免费档/会员档，人工在界面里文生图、图生图、文/图生视频、智能画布（局部重绘、扩图、消除、抠图）。
- 特点：支持中文提示词、参考图保持形象特征（画风保持/姿势保持/背景替换），利于角色一致性。

### 路径二：企业级 API（火山引擎 Volcengine）
- 入口：火山引擎「智能视觉控制台」→ 图像生成大模型 / 即梦AI（`https://console.volcengine.com/ai/overview`）。
- 即梦AI 系列模型 API 已于 **2025-09-02** 通过火山引擎全面开放，已开放核心接口：
  - 文生图：`seedream-3.0` / `seedream-3.1`
  - 图生图：`seedream-3.0`（风格转换、二次重绘）
  - 文生视频 / 图生视频：`视频生成-3.0-pro`
  - 数字人：`OmniHuman`；动作驱动：`Motion-1.0`
- 图片生成 4.0（即梦同源）接口：`https://visual.volcengineapi.com`，`POST`，`Action=CVSync2AsyncSubmitTask`，`Version=2022-08-31`；支持单次最多 10 张输入图、一次最多输出 15 张、4K 超高清。
- RESTful 端点示例：`https://api.volcengine.com/seedream/v1/images/generations`。
- 官方 SDK：Python / Node.js / Go（封装网关签名与调用）。
- **前置条件**：火山引擎账号 + **实名认证** + AccessKey(AK/SK) + 在控制台开通「图像生成大模型」能力（可选免费试用 / 正式调用）。

## 2. 免费额度 / 生成限制 / 商用授权核实（首轮，含待核实项）

### 已知约束
- **免费档**：每日登录赠 60–100 积分；免费生成作品**自带平台水印**；输出最高约 720P；积分**当日有效**；并发受限、高峰期排队；**仅个人非商用，禁止商用/发布盈利**。

- **图片 4.0 4K 限时免费**促销活动标注至 2026-11-06，临近到期，不可作为长期免费依据。
- **API 计费（火山引擎）**：图像生成约 ¥0.012/张起；视频约 ¥0.20/秒起；新用户可领 **1000 张 / 100 秒免费测试额度**。

## 3. 统一美术规范（D 混合风格，定稿）

> **依据纪律（第 121 轮新增）**：本规范是**设计决策**，不是游戏官方设定。代码里真正定义角色外貌的只有极少几处（如沈碑的"扫帚""观前""三千年"），其余外形全由本规范决定。
> 写作/汇报时必须区分 **「代码有据（canon）」** 与 **「设计补充」**——详见 `CHAR_SHENBEI_CARD.md §0.5`。**不得把设计补充冒称官方设定。**

> 视觉方向（此前已确认，**不得采用后来提出的降级视觉标准**，违者打回）：
> ① 东方水墨意境　② 高品质国风修仙手游 UI　③ 电影级玄幻场景　④ 现代精品 UI 设计。
> **明确禁止**：低精度、扁平简化、廉价量产风、与以上四项不符的廉价感。

本规范是 §4 提示词模板与后续所有素材生产的**唯一风格基准**。改稿/补模板前先回到本节。

### 3.1 色板（锚定，全素材通用）
| 角色 | 色值 | 用途 |
|---|---|---|
| 墨黑（主） | `#1A1A1A` | 主笔触、描边、文字 |
| 玄青（主） | `#0E1B2A` | 深景、夜场景底 |
| 宣纸米白（主） | `#F2EBDD` | 留白、面板底、背景 |
| 玉青（辅） | `#6FB7A6` | UI 描边、灵气、法宝辉光 |
| 金（辅） | `#C8A24B` | 描金、等级/稀有标识、称号 |
| 朱砂（辅·克制用） | `#B23A30` | 危险、血/煞气、警示，少量 |
| 月白（辅） | `#DCE6F0` | 月光、霜、冷调高光 |

- **留白比例**：画面 ≥40% 宣纸留白；UI 面板内留白 ≥30%（宁疏勿挤）。
- **色彩克制**：单图主色 ≤3，灵光/法宝辉光面积 ≤画面的 12%，避免「光污染」。

### 3.2 笔触 / 质感
- 水墨笔触：中高强度，主体边缘带**飞白 + 淡晕染**，不追求照片级写实。
- 宣纸质感：全局叠加 5–10% 颗粒噪点 + 极淡纤维纹理（不抢主体、不糊细节）。
- 禁用：塑料感高光、卡通描边加粗、重度磨皮、3D 渲染默认光影。

### 3.3 光影 / 氛围（三套基调，按场景选）
- **晨雾**：冷青薄雾 + 体积光，适合宗门清晨、野外。
- **月华**：月白冷调 + 柔光，适合夜修、秘境、塔内高层。
- **灵光**：玉青/金 点状辉光 + 丁达尔，适合技能、法宝激活、渡劫。

### 3.4 角色 / NPC（一致性优先的三类之一）
- 比例：7–7.5 头身，体态修长清瘦（修仙者而非壮汉）。
- 脸型锚点：**鹅蛋脸 + 剑眉 + 丹凤眼**，禁止网红脸/锥子脸/欧美立体骨相。
- 服饰色系锚点：以玄青/月白为基，玉青/金作点缀；同一角色须锁定主色与纹样。
- **一致性机制（核心）**：每位常驻角色建「参考图库」——
  正面立绘 / 半身 / 全身 / 表情三连 / 服装细节特写 各 1 张；
  后续生图一律以该角色的「参考图 + 画风保持 + 姿势保持」为输入，锁定 IP。
- **老年 NPC 适配（第 119 轮补）**：上述「7–7.5 头身 + 鹅蛋脸 + 剑眉 + 丹凤眼」针对**年轻修仙者**。老年 NPC（如沈碑）保留「国风骨相·清正·不网红」内核，允许白发、长眉、皱纹、三缕须、脊背微驼；体态约 7 头身、清瘦不弱。首个落地样本见 `CHAR_SHENBEI_CARD.md`。

### 3.5 场景（一致性优先的三类之一）
- 景深：前 / 中 / 后 三层，以雾气过渡，避免平涂。
- 构图：三分法 + 留白，主体偏下或偏侧；竖屏素材优先 9:16 与 3:4，横屏 16:9。
- 四类场景基调用色：
  - 塔内（镇妖塔）：玄青 + 朱砂禁制纹，冷硬、压迫感。
  - 宗门：宣纸米白 + 玉青 + 金檐，清雅、秩序。
  - 野外：晨雾 + 墨绿远山，开阔、留白。
  - 秘境：月华 + 灵光，奇诡、幽深。

### 3.6 UI（现代精品，与游戏现有素墨宣纸体系衔接）
- 圆角 8–12px；描边 1px 玉青/墨金渐变；忌重黑粗边。
- 材质：玉（半透磨砂）/ 金（仅描边不过光大面）/ 墨（底纹）。
- 间距：8px 栅格，面板内边距 ≥16px。
- 与现有 `style.css` 素墨宣纸基调保持一致（不另起视觉语言，避免风格割裂）。

### 3.7 固定负面词（全模板共用，见 §4）
`低精度, 模糊, 畸形, 多指, 水印, 平台logo, 文字错乱, 塑料感, 过度饱和, 廉价贴图, 二次元夸张比例`

## 6. 素材目录 / 命名 / 版本管理 / 质量验收（首版，对齐现有 `ui/`）

### 6.1 目录（实际）

### 6.2 命名
- NPC/角色：`ui/npc/<id>_<variant>_v<n>_<status>.png`，`variant ∈ avatar|half|full|expr1..3|scene`，`status ∈ candidate|final`。
- 图标：沿用 `ui/icons/<category>_<id>.png`（如 `beast_rat.png`）。
- 规则：**全小写、下划线分隔、无空格、无中文**；`final` 才进代码引用。

### 6.3 尺寸/格式（摘要，详见 `CHAR_SHENBEI_CARD.md §3.1`）
- 全身立绘 1080×1920 PNG-24 透明；半身 1080×1440 PNG-24 透明；头像 512×512 PNG-24 透明；场景 1080×1920 / 1920×1080 不透明 JPG/PNG。
- 单张 ≤500KB；sRGB。

> **第 121 轮补充（重要）**：**战斗立绘必须透明**。现有 `hero_male.png`(1080×1134)、`hero_female.png`(1080×1061) 是**带背景**的图，直接叠在战斗台上；换精修图时必须出透明版，否则战斗台出现白底方块。此项已列入 `ART_ASSET_MASTER_LIST.md` P-01/P-02 的验收（QA-A1）。
> 另：Boss 目前只有 384 图标，战斗放大即糊——Boss 立绘（M-02，1080×1440 透明）为 B 级必需项。

### 6.4 版本与元数据
- `v1/v2…` + `candidate/final`；候选与定稿并存，可回滚。
- 每张 `final` 记录：平台/模型/档位、水印有无、授权状态、日期；写入 `ui/CREDITS.txt` + `art-pipeline/CREDITS_LEDGER.md`。

## 7. 接入现有游戏技术方案（首版要点，仍属设计，不改代码）

- 现有架构：原生 HTML/CSS/JS，双击 `index.html` 可运行，localStorage 存档，**无构建工具、无框架、零 npm 依赖**。
- **路径**：并入现有 `ui/`（NPC → `ui/npc/`），全部相对路径引用；不引入 `assets/` 新体系。
- **占位优先**：先保证"无图也能跑"——如 `ROBES[].imgM/imgF` 留空时走内置 `avatarSVG()`；NPC 图缺失时走文字/印章占位（现有 `nv-seal`「碑」即占位心智），**有图才替换**，绝不因缺图报错。
- **按需加载**：立绘/场景用 `loading="lazy"` 或进入识人页再 `img.src` 赋值；避免首屏拉大图。
- **不改均衡**：不触碰 `needG=1.85`、`combatPower()` 与任何数值/存档结构（AGENTS.md §1/§5）。
- **兼容风险**：旧存档、转世、重开、离线时间、重复点击、模块加载顺序；接入时按 §7.1 备份→改→测→同步走。
- **落地顺序**：沈碑 `final` 图入 `ui/npc/` → 识人页 `img` 引用（回落到印章占位）→ 主角五套服饰按 `ROBES.imgM/imgF` 填路径（现有机制已预留，只填不改）。
