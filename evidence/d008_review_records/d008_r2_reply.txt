二、唯一剩余问题：fx 本身没有类型契约

这是我检查第二轮完整专项测试源码后发现的。

目前两处 chkFx 都有类似逻辑：

JavaScript
const chk = (fx, id) => {
  if(!fx) return;
  Object.keys(fx).forEach(k => ...);
};

运行时校验也一样：

JavaScript
const chkFx = (fx) => {
  if(!fx) return;
  Object.keys(fx).forEach(k => ...);
};

问题在于：if(!fx) return 把 null、false、0、空字符串都当成合法的空效果跳过了。

但本批声明的契约是：

纯叙事效果使用 {}；

有效果的选项使用符合既有字段白名单的对象；

不新增其他效果结构。

那么 fx: null 就不应被当成合法的纯叙事效果。

当前专项测试：

JavaScript
assert.ok(o.fx !== undefined, id + '#' + i + ' 有 fx');

同样会接受 fx: null。

当前运行时校验：

JavaScript
if(!o.label || o.fx === undefined) meta++;

也会接受 fx: null。

这不是说当前 34 条奇遇中真的存在 fx: null。我检查了你展示的新增内容，实际条目使用的都是对象，没有发现产品内容因此出错。

问题在于：契约测试没有完全保证以后不会把合法的 {} 意外改成非法的 null。

建议的最小修复

专项测试和 verify.js 采用一致规则：

JavaScript
const validFx = fx =>
  fx !== null &&
  typeof fx === 'object' &&
  !Array.isArray(fx);

然后在遍历每个选项时检查：

JavaScript
if(!validFx(o.fx)) {
  // 专项测试：直接 assert 失败
  // verify.js：计入 meta 或 badShape
}

并且 chkFx 自身也应防御非法输入，不能只依赖调用者事先检查。

嵌套结构也建议明确约束：

boost 必须是非数组对象，且只允许 mult、sec。

roll 必须是数组。

每个 roll 分支必须是非数组对象，且只允许 w、text、fx。

分支中的 fx 也必须是合法对象。

当前 boost 的额外字段检查和 roll 分支额外字段检查方向正确，不需要推翻，只需补上类型边界。

三、ok 字段的语义判定：接受开发方解释

这一点我明确撤销第一轮的笼统要求。

根据你提供的真实引擎代码：

JavaScript
let detail = o.ok || '';
if(o.fx && o.fx.roll && o.fx.roll.length){
  detail = hit.text || '';
}

roll 选项的 ok 确实会被分支文本覆盖。

所以：

新增非 roll 选项必须有 ok；

新增 roll 选项可以不提供 ok；

既有四条奇遇不因本批审查被要求改写。

这是与实际引擎行为一致的契约，不属于放宽测试。
