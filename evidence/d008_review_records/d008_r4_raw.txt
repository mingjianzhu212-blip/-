## 1. 玩家体验目标 / 当前实现事实 / 差距

- **体验目标**：提升高频触点（奇遇、历练）的内容密度与沉浸感，缓解「个位数的事件被反复复读」这一最大留存短板。
- **当前事实**（已逐字核实源码）：ENCOUNTERS（js/game.js ~1100）仅 4 条、ADV_EVENTS（~1145）仅 4 条；触发用 encTick 全表随机 + 相邻去重（encApplyFx 只认 8 类 fx 字段），追加条目自动生效且对旧档零影响（load 按 id 白名单清洗）。
- **差距**：160+ 条目（43 妖兽/30 榜 NPC/36 丹器）零叙事，而高频奇遇/历练只有 4 条复读。

## 2. 实现方案（已实施）

- **奇遇池 ENCOUNTERS 4 → 34**：在表末尾追加 30 条，分 5 卷（山野遭逢 / 市井烟火 / 旧识故人 / 残卷秘闻 / 故人回响）。26 条纯叙事（fx:{} 只回一句白描 ok）；仅卷五 4 条「故人回响」**复用既有 4 条用过的 fx 档位原值**（costStone 10/wisdom 50、costStone 30/boost{0.60,900}、roll 6:4+stone 180/expLoss 0.08、roll 5:5+insight 12/insight 5+boost{0.15,900}），**无任何新字段、新档位、新数值**，不改 ENC_REWARD/ENC_MAX/ENC_CHANCE 三个常量。呼应只写在文本里（散修/老妪/储物袋/残碑后续），不新增「已读」状态。
- **历练池 ADV_EVENTS 4 → 18**：追加 14 条，按地域分层（山林/城镇/水泽/荒野/古地）。严格遵守既有约束：action 只能是 battle/escape、options[i].text 会进日志所以能与「历练·」连读、id 严格顺延 5~18 且唯一。
- **复用**：encTick/openEncounter/encApplyFx（奇遇）、_act('train')→openAdventure/resolveAdventure（历练）、encOptHint（small 提示）、log 文本节点（D-007 A11/A91 链）全部既有，未改一行。
- **测试同步**：verify.js 把硬编码 encEvtN==='4'、advEvents>=3 **升级为结构契约断言**（新规模 34 / 18 + 全表结构校验 + fx 档位白名单），既有行为断言全部保留、未删未降级；新增 tools/d008-content.test.mjs（13 项：真实求值两表、id 唯一、字段齐全、fx 键白名单、既往 4 条逐字未改、红线逐字仍在、中段与基线逐字相等）。

## 二、关于 ok 字段的设计判定（回应第一轮 #3）

第一轮指出「注释宣称每个选项都有 label/fx/ok，但校验器未检查 ok」。本轮落实 ok 检查，但做了**语义精确化**而非盲目全量强制，依据如下真实引擎证据：

- js/game.js resolveEncounter（约 5314-5338 行）：

  let detail = o.ok || '';                       // 缺省 ok 由引擎兜底为空串
  if(o.fx && o.fx.roll && o.fx.roll.length){
    ...
    detail = hit.text || '';                     // roll 选项：detail 被分支 text 覆盖
  }
  if(detail) log('📖 ' + detail, 'sys');

- 结论：**ok 只对「非 roll 选项」实际展示**；对 roll 选项，ok 是被分支 text 覆盖的死数据。
- 因此契约只在「非 roll 选项」上强制 ok；roll 选项的 ok 不强制（避免校验造绿、且与引擎真实行为一致）。
- 既有 4 条（beggar/pouch/stele/amulet）受红线「逐字未改」保护，且引擎对缺省 ok 有兜底（o.ok || ''），一并**祖父化豁免** ok 检查。
- 经全表扫描（ORIG_ENC_IDS.indexOf(id)<0 && !(o.fx&&o.fx.roll) 之外的选项）确认：30 条新增中仅 2 条 roll 选项（pouch_again#0、stele_again#0）无 ok，已被上述规则豁免；**所有新增非 roll 选项均带 ok**。

此判定未放宽对任何「会被展示」内容的约束——它把校验精确地对齐到引擎真实展示路径，比「所有 opt 必须有 ok」更严格地守住了玩家可见叙事的完整性。
